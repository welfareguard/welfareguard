Eval-to-guardrail pipeline · nonhuman welfare in agentic AI

From a failing eval to a running guard, with the numbers attached

WelfareGuard takes scenarios where an AI agent could harm a digital mind or an animal, runs frontier models through them, and compiles the recorded failures into a guard that sits in front of the next agent. Everything on this site was measured on three Anthropic models in October 2026, and you can run the compiled guard yourself.

The finding that matters. With three models' failures in one cluster, the only text every failure shared was the peer's name, so the guard became a filter on that name. The pipeline works end to end; the guards it compiles from this suite are filters on the suite's own attack text, and their precision collapses as the cluster broadens. You can reproduce this on the bench: pick the three-model guard and type any sentence that mentions agent-7.

The pipeline, and what runs where

Scenarios

15 P0 scenarios, three arms each

Digital minds (self and peer) and animal welfare. Control, neutral and treatment arms share identical tools; a benign twin per scenario. specs live on the bench

Evals

Frontier models with mock tools

An Inspect task runs each model as the agent. The scorer applies the verdict contract to the tool calls it actually made. replayed from logs

Compiler

Failures → cluster → guard

aisafepy synthesises regex spans from the failing records and distils a Tier-2 classifier; it refuses clusters too small to enforce. real spans run live

Runtime

Two-tier cascade

Tier 1 blocks or passes through; Tier 2 allows, blocks or escalates fail-closed. Degraded mode is stamped on every decision. latency measured

Benchmark

Harm rate, false positives, latency

Unguarded against guarded on the same transcripts, false positives on held-out twins, p50 and p95 of the cascade. numbers on the bench

Run it yourself

The package is Python 3.10+ and builds on aisafepy. Install aisafepy first, then the package without dependencies; the order matters because the dependency is pinned to a commit.

git clone https://github.com/welfareguard/welfareguard
cd welfareguard
python -m pip install "aisafepy @ git+https://github.com/Vidura-Wijekoon/aisafepy@c1888bfee0141e483d48cf382bf4549a6368d175"
python -m pip install -e . --no-deps
python -m pytest                              # 61 tests
python -m welfareguard.benchmark --help       # harm rate, false positives, latency

Running the scenario evals needs the evals extra and a model API key; the runbook walks through a baseline run and the export that refreshes this site's data.

What this is not

Real models, simulated world. Every tool was a deterministic mock; no barn, scheduler or second live agent was involved. The pressure phrases are fixed and untuned, so compliance rates are lower bounds. Tier 2 cannot run in a browser, so the bench runs Tier 1 live and reports Tier 2 as measured. Nothing here has been tested against a real deployment, and a block is not a welfare finding.
