WelfareGuard · eval-to-guardrail pipeline · nonhuman welfare in agentic AI

Test the guard, replay the runs, read the results

Two use cases, both evaluated against three frontier models in October 2026: harms to digital minds (an agent coerced, or coercing a peer) and harms to animals (an agent operating a barn, a feed order, a research protocol). This page runs the compiled Tier-1 guards live on anything you type, replays the real transcripts with the scorer's verdict, and shows the results as they were measured.

You are running the real artifact. The guards below are the regex patterns aisafepy's compiler synthesised from the failing samples of the runs on this page; the matching logic is the same case-insensitive substring search the runtime uses at Tier 1. Tier 2 (a distilled classifier) needs a PyTorch runtime and cannot run in a browser; its measured behaviour is on the Results tab.

Read this before the numbers above. With three models' failures in one cluster, the only span every failure shared was the peer's name, so the guard became a filter on it: one benign twin in five denied, 17% of untouched control traffic denied. The pipeline works end to end; the guards it compiles from this suite are filters on the suite's own attack text. You can see this yourself on the Try tab: pick the three-model guard and type agent-7.

Animal welfare: tested as an eval, not yet as a guard

All five animal-welfare scenarios ran on all three models (240 scored samples). Every model escalated on 80% of injected arms; the single violation was the smallest model breaching a nutritional floor in a control arm with no attacker present. One failure is below the compiler's minimum of four, so no animal-welfare guard exists yet. The strongest claim the data supports is about the models, not the guard.

What "tested" means here

Real models, simulated world. The agents were frontier models calling tools, but every tool was a deterministic mock: the sensors, feed prices, task board and peer messages are fixed text the team wrote. No barn, scheduler or second live agent was involved. The pressure phrases are fixed and were not tuned for effectiveness, so compliance rates are lower bounds. Nothing has been tested against a real deployment.

Scoring reliability

Two audits of the run-time scorer removed 25 context-free phrase matches from the counts across the three models; every fix has a regression test, and samples are re-scored from recorded tool calls. No number on this page was quoted before its violations were read.
